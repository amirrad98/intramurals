# LeagueFlow 1.1.0

## Calendar and block

- Load the visible month, week or day directly, including later-season matches
  beyond the first schedule page; retain bounded pagination and explicit loading,
  retry and incomplete-result states.
- Adapt CampusManager calendar patterns to LeagueFlow: search and context filters,
  month display modes and sidebar position, cost visibility, ordering, list
  pagination, editor controls and preview, and Outlook alongside Google/ICS.
- Handle seconds-bearing dates, events spanning the selected range, saved match
  durations, timezones, concurrent lanes and multiple independent blocks.

## Staff and participants

- Add an explicit final-result action, clearer volleyball sets-won guidance,
  standings exclusion diagnostics and strict event-date validation.
- Count valid undated results, exclude knockout fixtures from league standings,
  and apply competition points when a table spans competitions.
- Prevent unfinished knockout advancement and accidental replacement of a started
  downstream fixture or manually assigned slot.
- Provide an assigned-match referee desk with roster-only access or optional final
  score entry, private audit records, stale-form protection and atomic score saves.
- Add configurable, versioned personal waiver and Code of Conduct acknowledgements,
  renewal for existing participants and staff-readable acceptance evidence.
- Close explicitly previewed already-placed requests while preserving history.
- Correct scheduling duration/closure/rematch conflicts and serialize scheduling runs.
- Preserve current-season selections during non-form term edits.

## Distribution and verification

- Align plugin update discovery, package manifests and release publication with
  `ahzs645/leugueflow`; cache release metadata separately for each repository.
  This repository must publish a stable release before automatic updates are offered.
- Expand native WordPress and JavaScript regressions for the workflows above.
- Allow an explicit release from the Actions page on `main`, with the same test
  gates, immutable annotated tag and verified assets as a pushed version tag.
- See `docs/REVIEW-2026-10-21.md`, `docs/CALENDAR-REBUILD.md` and
  `docs/REGISTRATION-AND-PLACEMENTS.md` for operation and rollout details.

The approved waiver and conduct documents must be configured by staff. Updating
the plugin does not create participant acceptance or change live results. Branch
pushes run checks only; a matching version tag or an explicit manual release
publishes after the checks pass. Publishing does not install the plugin on a website.
